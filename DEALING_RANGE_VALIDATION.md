# Dealing Range: генерация → проверка → ручное решение

> Обновление 17 ноября 2026: после уточнения правил пользователем эта исходная
> проверка заменена [DR_SEQUENCE_AUDIT_RU.md](DR_SEQUENCE_AUDIT_RU.md).
> Автоматический последовательный DR теперь может быть ESTABLISHED, с EQ и
> Premium/Discount. Значимость для сделки и Confirmed Narrative остаются отдельными.

Генератор `rangeCandidates` перечисляет геометрические пары подтверждённых Fractal 3.
`validateDealingRangeEvidence` отдельно проверяет границы и контекст. Эти функции
не выбирают «значимый импульс» по выдуманному числовому порогу.

Проверка возвращает high/low ID, origin, confirmed_at, lifecycle, consumed,
raid_at, coverage, пригодность для review, ссылки на HTF-контекст,
условие собственного TF close вне выбранного диапазона и список требований.
Компактная выдача показывает сначала кандидата с наблюдаемыми целыми границами,
остальные считает omitted; полный список доступен в Intelligence.
Явно выбранная пара H4 не смешивается с автоматически сгенерированным кандидатом.

| Архивный NAS100 Bid | Границы | Candidate suitable for review | Active DR / PD |
|---|---|---|---|
| MN1 26980.6–30758.3 | CONSUMED / CONSUMED | false | false / null |
| W1 26255.2–30015.8 | ACTIVE / ACTIVE, наблюдаемое покрытие | true | false / null |

Числа относятся только к `2026-11-16T07:17:59.382Z`, Capital.com Demo.
[ID, происхождение, подтверждение и raid](verification/capitalive-v5-1/dr-controls.json).
Геометрический EQ `(high + low) / 2` не маркируется как действующий Premium/Discount.
Consumed boundary не доказывает, что вся зона потеряла смысл; он препятствует
автоматическому использованию границы как неснятой ликвидности.

Протокол DealingRangeReview:

1. Зафиксировать symbol, side, environment, as_of, evidence SHA и конкретные ID.
2. Проверить происхождение Fractal 3, закрытие третьей свечи, доступную историю и raid.
3. В защищённом inspector проверить импульсное происхождение, значимость, связь с
   KL и X−1/X−2; различить расширение старого range и новый range.
4. Записать обоснование актуальности обеих границ и инвалидацию отдельно от Entry.
5. Сохранить ручное решение отдельно от автоматического кандидата. При смене
   evidence SHA пересмотреть его. Не принимать наличие пары/галочки за авторское
   доказательство. Без достаточной спецификации оставить REVIEW_REQUIRED и PD null.

V5.1 предоставляет материал для этого review; автоматическое HUMAN_VALIDATED и
активация PD не реализованы намеренно, поскольку необходимые качественные
критерии не определены однозначно. Existing explicit high_id/low_id selector и
snapshot-bound review сохранены. 23 локальных HTTP-проверки включают точный выбор
H4 по фракталам, а browser test проверяет обновление EQ и ссылок после выбора.
