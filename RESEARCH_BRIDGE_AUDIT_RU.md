# Capitalive Research Bridge V1 — аудит

Дата: 15 ноября 2026. Исходная ветка: `feature/the-edge-knowledge`, [PR #2](https://github.com/Yilin1207/capitalive/pull/2). Базовая версия V3 — `ccb8cb413d93b2abc5a87e49e7126129014f6f85`; реализация Bridge — `c843eef6b04c33086f01290de03567e8e6827deb`.

## Что создано

Защищённый `GET /api/desk-report?symbol=EURUSD&side=bid` выдаёт `desk-report-v1`. Поддерживаются EURUSD, NAS100, EU50 и стороны Bid/Ask. По умолчанию автоматизация сохраняет Bid-анализ, одновременно показывая обе цены котировки.

Движок THE EDGE выполняет прежние расчёты. Новый слой только отбирает и упаковывает результаты: `lib/research-bridge/report.ts`, `contract.ts`, `http.ts`. Файлы `lib/knowledge/*`, загрузчик свечей и торговая логика в этой работе не изменены. Автоторговля отключена, итоговое действие Bridge — WAIT.

Отдельный приватный репозиторий: **[Yilin1207/capitalive-research-bridge](https://github.com/Yilin1207/capitalive-research-bridge)**. Туда публикуются только:

- `reports/latest/EURUSD.json`
- `reports/latest/NAS100.json`
- `reports/latest/EU50.json`
- `reports/latest/manifest.json` — время пакета, размеры и SHA-256 трёх файлов.

Все четыре файла меняются одним Git-коммитом. Старый успешный отчёт не подставляется при недоступности нового: для проблемного актива записывается ERROR. Если недоступен сам GitHub или остановлен Actions, остаётся предыдущий коммит; его устаревание определяется по `expires_at`, а не по факту наличия файла.

## Содержание и пределы компактного формата

Предел каждого JSON-файла — **65 536 байт UTF-8 вместе с конечным переводом строки**. Сохраняются:

- Bid, Ask, spread, источник REST/WebSocket, статус рынка; время провайдера отдельно от времени получения.
- `generated_at`, общий `as_of` анализа, `expires_at`, Demo/Live, версия и коммит реализации.
- MN1/W1/D1/H4: число закрытых свечей, конец последней закрытой свечи, fetched_at, качество, структура и проектный swing bias.
- Последний подтверждённый high/low для **обеих** версий фрактала 3/5 на каждом TF; последние BOS/CHOCH, SNR, RB, FVG и raid.
- Выбранный A и активные HTF-кандидаты; до трёх B с исходной допустимостью и препятствиями; C из исходного результата или null; раздельные Entry/KL/Narrative invalidations.
- Явный Dealing Range, если он задан исходному движку. Без выбранных фракталов — null и `EXPLICIT_SELECTION_REQUIRED`, без автоматически придуманного диапазона.

Выбор по давности — **политика отображения**, не новый алгоритм выбора цели. Для каждой категории указаны total/omitted. iFVG/IDM/Strong представлены счётчиками без дополнительных примеров по умолчанию. До четырёх препятствий на B; оставшиеся учтены в omitted, путь помечается PARTIAL. Неполный или неоценённый путь не означает отсутствие препятствий. Для полного исследования остаётся исходный защищённый Intelligence API.

Все показанные элементы ссылаются на `evidence.eN`: **исходный ID, origin, confirmed_at**, границы, состояние, качество и правило. Связанные KL/фракталы/события включаются рекурсивно, даже если не входят в обычную квоту отображения. Короткая ссылка не заменяет оригинальный ID — он хранится один раз. Общие правила и версии источников вынесены в `rules`.

`candle_refs` и lifecycle `candle` ссылаются на `candle_windows`: пары **время открытия / время закрытия**, без OHLC. Сохранён SHA-256 исходного свечного доказательства. Это позволяет проверить связь с серверным доказательством, но не воспроизвести все ценовые расчёты только по компактному файлу: полная история намеренно не публикуется.

При превышении лимита возвращается `ERROR / REPORT_TOO_LARGE`; обязательные зависимости не обрезаются незаметно. Ограничение может сработать на более сложном будущем наборе, даже если текущие шесть проверенных отчётов укладываются. Повышать лимит или менять политику отображения следует отдельным изменением контракта.

## Причинность и качество

Формирование отчёта не повышает Candidate Narrative до Confirmed. Статус, направление-кандидат и факт ручного подтверждения берутся из исходного результата отдельно. В проверенных автоматических отчётах `confirmed_narrative = null`.

Проверяются закрытие всех свечей доказательства не позже подтверждения элемента, подтверждение не позже as_of, собственные интервалы lifecycle, соответствие symbol/side, разрешимость ссылок и наличие подтверждающей свечи. Будущие, противоречивые или неполные доказательства отклоняются.

`STALE` выставляется при неизвестном/старом времени котировки, отсутствии корректных Bid/Ask, устаревшем входном снимке либо H4 старше восьми часов. Выходной день не даёт оснований считать старую котировку свежей. Это консервативная политика доставки, не изменение рыночного календаря THE EDGE.

`fresh` означает свежесть **в момент генерации**. При чтении позже необходимо заново сравнить provider timestamp с текущим UTC: допустимый возраст котировки — 300 секунд. `expires_at` — предел актуальности пакета до следующего номинального H4-закрытия плюс 20 минут, а не гарантия свежести цены на весь этот срок. Пропущенный запуск не продлевает срок.

Отсутствующий provider timestamp остаётся null. Время HTTP-получения, close H4 и mid не подставляются вместо него. Общая доказательность остаётся PARTIAL/UNVERIFIED; Bridge не присваивает VERIFIED, вероятность TP или доказанную прибыльность.

## Тесты

- **223/223** unit/integration/regression, в том числе 15 новых тестов Bridge.
- Шесть сохранённых входов: EURUSD/NAS100/EU50 × Bid/Ask. Исходный Intelligence не мутирует, Narrative совпадает, IDs и confirmation times сохранены.
- Будущие свечи/элементы, неверная сторона, потерянная ссылка, неправильный рынок, неизвестные поля, oversized JSON, просроченный ответ и фиктивное подтверждение отклоняются.
- Синтетические секреты в account/password/error/личных комментариях не попадают в отчёт; проверяются запрет raw OHLC и отказ записи в публичный репозиторий.
- Publisher без npm-зависимостей отдельно проверен на Node 24: три отчёта и manifest записываются атомарно, без force push; HTML/redirect/oversize превращаются в ERROR.
- TypeScript и Next build прошли. [GitHub Release checks](https://github.com/Yilin1207/capitalive/actions/runs/43727363386) на реализации прошли, включая replay, 8 Playwright-сценариев и прежние HTTP-контракты.
- Реальные Preview HTTPS: все три рынка на обеих сторонах. Реальные GitHub Actions: проверка конфигурационного PR, автоматический запуск после активации и успешный workflow_dispatch.

Сводные доказательства без полных рыночных отчётов: `verification/research-bridge-v1/audit.json`. Сами актуальные отчёты находятся только в приватном репозитории доставки. Успешные тесты формата не являются независимой экспертной проверкой торговой логики.

## Автоматизация и безопасность

В отдельном репозитории через [конфигурационный PR #1](https://github.com/Yilin1207/capitalive-research-bridge/pull/1) включён workflow Research Bridge. Этот инфраструктурный PR принят после CI; **PR #2 основного приложения не слит**, production не развёртывался.

Расписание: **00:17, 04:17, 08:17, 12:17, 16:17, 20:17 UTC** (`17 0,4,8,12,16,20 * * *`), после номинального закрытия H4. Для Asia/Qyzylorda это 05:17, 09:17, 13:17, 17:17, 21:17 и 01:17 следующего дня. Ручной запуск: Actions → Research Bridge → Run workflow → main.

Cron настроен на default branch отдельного репозитория. [GitHub предупреждает](https://docs.github.com/en/actions/reference/workflows-and-actions/events-that-trigger-workflows#schedule), что расписание может задерживаться или пропускаться. Срабатывание будущего cron ещё не наблюдалось; тот же путь публикации реально проверен ручным запуском. Остановка при исчерпании текущих квот Actions не маскируется; платный тариф или billing не менялись.

В GitHub нет Capital.com ключей, торговых аккаунтов, исходных OHLC и персональных полей рецензента. Для записи применяется краткоживущий job `GITHUB_TOKEN` с `contents: write` только в отдельном репозитории. Исходный PAT/GCM-токен не сохранён в Actions.

`BRIDGE_BASE_URL` — Actions variable с проверенным immutable Preview. Отдельный Vercel bypass хранится в **зашифрованном Actions secret** `VERCEL_AUTOMATION_BYPASS_SECRET`, передаётся только заголовком, не URL. PR-тесты его не получают. Этот ключ намеренно сохранён для автоматизации; его scope — весь Vercel-проект, не один endpoint. Доступ на запись в приватный репозиторий и его Actions следует давать только доверенным операторам. Ротация: создать новый dedicated bypass, заменить Actions secret, отозвать старый; остановка: Disable workflow и отзыв bypass.

Vercel SSO осталось `all_except_custom_domains`; production target остался `capitalive-2rnu3zimh-yilin1207s-projects.vercel.app`. Новая версия приложения существует только в Preview. Отключать SSO для подключения ChatGPT не требуется.

## Подключение к ChatGPT

1. Открыть ChatGPT → **Settings → Plugins → GitHub** и авторизовать GitHub app. Выдать доступ к **Yilin1207/capitalive-research-bridge**; доступ к исходному приложению для чтения отчётов не требуется.
2. В поддерживаемом режиме попросить прочитать `reports/latest/manifest.json` и JSON нужного актива из текущей default branch. Доступность GitHub зависит от тарифа, workspace и поверхности продукта; иногда доступен deep research/agent, но не обычный чат.
3. Проверить, что ответ цитирует свежий файл/коммит, generated_at, as_of и статус. При недоступном приватном файле модель должна сообщить об этом, а не продолжать анализ по памяти.
4. Не передавать ChatGPT GitHub-токен, Vercel bypass или Capital.com ключи. Скачанный вручную JSON — снимок; сам он обновляться не будет.

Пример запроса:

> Прочитай в Yilin1207/capitalive-research-bridge файл reports/latest/manifest.json, затем reports/latest/EURUSD.json. Сначала назови коммит, generated_at, as_of, статус и provider timestamp котировки. Проверь срок актуальности по текущему UTC. Затем объясни MN1 → W1 → D1 → H4, кандидаты A/B/C, препятствия и инвалидации. Для выводов укажи исходные IDs и confirmed_at через evidence. Не превращай Candidate в Confirmed и не считай PARTIAL-путь свободным от препятствий. При STALE/ERROR не выдавай данные за текущий торговый сигнал.

Актуальное основание инструкции — [официальная документация OpenAI](https://help.openai.com/en/articles/11145903-connecting-github-to-chatgpt): GitHub читается по запросу, это не управляемый синхронизированный индекс. Настройка разрешений GitHub app в аккаунте пользователя и чтение файлов именно из его ChatGPT **ещё не проверены**. Серверная генерация, приватная доставка и ручная автоматизация проверены отдельно и не выдаются за завершённую проверку пользовательского подключения.
