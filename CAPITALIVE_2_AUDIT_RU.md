## Результаты аудита исходной реализации

| Область | Что обнаружено | Что сделано |
| --- | --- | --- |
| `/api/structure` | Возвращает OHLC, но не рассчитывает фракталы, диапазоны, FVG или цели. Интерпретацию полностью выполнял клиент. | Добавлен отдельный детерминированный анализ и `/api/market-audit`; старый контракт сохранён. |
| `/api/quotes` | Уже различает время провайдера и HTTP-получения, имеет WebSocket/REST и stale-флаги. Нельзя считать REST без полного timestamp свежим тиком. | Нормализация вынесена в общий модуль без изменения старого контракта. Аудит получает только нужный инструмент и заново проверяет возраст даже при попадании в кэш. |
| MN1 | Уже агрегируется из DAY по календарным месяцам UTC, отдельно для BID/ASK. Полнота торговых сессий не доказана. | Существующая агрегация сохранена и проверена; неполный месяц и пропущенный календарный месяц не могут подтвердить новый паттерн. |
| Закрытие свечи | Используется следующая свеча либо истечение номинального периода. Это вычисленная оценка, а не флаг провайдера. | Фрактал требует закрытия всех пяти свечей; формирующаяся правая свеча никогда не подтверждает его. В документации сохранён предел достоверности. |
| Отброшенные строки | Диагностические списки ограничены, поэтому алгоритм мог бы не увидеть все разрывы. | Добавлен полный `metadata.validation_gaps`; известные пропуски не соединяются в паттерн. При неизвестном времени отброшенной строки подтверждения подавляются. |
| BID/ASK | Независимые экстремумы нельзя объединять в достоверную свечу MID. | `side=bid` или `side=ask` последовательно применяется к свечам, фракталам, FVG, диапазонам, графику и опорной котировке. |
| Графики | Был интерактивный свечной график, но не было серверного PNG и структурных слоёв. | Добавлены общий SVG-рендерер, PNG API и слои в интерфейсе. Цены не генерируются и пропуски не заполняются. |

Проверены официальные параметры Capital.com: `WEEK`, `DAY`, `HOUR_4`, максимум
1000 строк и UTC-фильтрация исторических запросов. Месячная агрегация по DAY соответствует
отсутствию нативного MN1 в этом списке. Источник: [Capital.com Public API](https://open-api.capital.com/).

Причина неоднозначной интерпретации ChatGPT — отсутствие в старом ответе формализованных
сущностей и правил выбора. Одни и те же OHLC позволяли клиенту выбрать локальный экстремум
вместо фрактала, произвольные границы диапазона или исходный размер уже почти заполненного
FVG. Новые ответы явно отделяют подтверждение, снятие, остаток и аналитическое правило выбора.

## Реализованные правила

**Фракталы.** Строгие сравнения центрального High/Low с двумя свечами с каждой стороны;
равенство отклоняет фрактал. Возвращаются ID, цена, время, timeframe, side, статус,
время подтверждающей свечи и расчётное время подтверждения. `status=confirmed` отдельно
от `liquidity_status=untouched|swept`. Снятием считается касание или пересечение уровня,
в том числе текущей незакрытой свечой. Для ожидающих подтверждения используется `forming`.

**Диапазоны.** Выбирается последняя корректная пара противоположных подтверждённых
фракталов в хронологическом порядке. Границы содержат сами фракталы, EQ точно равен
`(high + low) / 2`. Возвращаются Premium, Discount, положение опорной цены, до 12
альтернатив, число пропущенных альтернатив и объяснение выбора. Потенциальные диапазоны
помечены `unconfirmed`; при отсутствии границы EQ равен null. BOS/CHOCH не требуется.
Снятая граница не удаляет исторический диапазон: это отдельно отражает `boundaries_swept`.
Сила реакции не выдумывается (`reaction_strength=null`).

**FVG.** Трёхсвечный разрыв между тенями первой и третьей свечи; подтверждение требует
закрытия всех трёх. Возвращаются исходные и остаточные границы, размер цены и единиц,
процент заполнения, направление, дата формирования, последнее касание до полного
заполнения и `untouched|partial|filled`. Заполнение — максимальное проникновение тени
после третьей свечи, включая текущую. Это ценовой интервал, не объём сделок.

Малые и заполненные FVG остаются в JSON. Значимость считается по остатку:
`max(min_remaining_units, ATR14 × atr_fraction / unit_size)`. По умолчанию EURUSD —
0,5 пипса, NAS100/EU50 — 1 индексный пункт, ATR fraction — 0,02. ATR — простое среднее
True Range до 14 закрытых свечей, с раскрытием числа наблюдений. Настройки передаются
через query string. Порог — явная эвристика, а не вероятность. Тест остатка EURUSD
0,2 пипса подтверждает: он остаётся видимым и не становится значимой целью.

**Цели.** От опорной цены выбранной стороны отдельно вверх и вниз выбирается ближайший
подходящий нетронутый подтверждённый D1/W1/MN1 фрактал либо граница значимого остатка
D1+ FVG. H4 остаётся промежуточным препятствием. Возвращаются альтернативы, препятствия
до ближайшей цели и значимые зоны, внутри которых уже находится цена. Снятые фракталы,
полностью заполненные и незначимые FVG исключены из допустимых целей. Не выдаются
BUY/SELL, EDGE, вероятность или обещание достижения цели.

**Согласованность.** Проверяется, лежат ли экстремумы закрытых вложенных D1/H4 свечей
внутри закрытых MN1/W1/D1. Формирующиеся свечи разных снимков не сравниваются как
синхронные. Отсутствие противоречий не доказывает полноту истории или торговых сессий.

## Новые endpoints и работа ChatGPT

После публикации в существующий настроенный Vercel-проект:

```text
GET /api/market-audit?symbol=EURUSD
GET /api/market-audit?symbol=NAS100&side=bid
GET /api/market-audit?symbol=EU50&timeframe=H4
GET /api/market-audit?symbol=EURUSD&include_candles=1

GET /api/chart?symbol=EURUSD&timeframe=H4
GET /api/chart?symbol=EURUSD&timeframe=MN1&side=ask
GET /api/chart?symbol=NAS100&timeframe=D1&fractals=1&fvg=1&ranges=1&eq=1&bars=120
```

Аудит запрашивает 60/120/200/240 свечей MN1/W1/D1/H4. По умолчанию OHLC доступны
через `structure[timeframe].candles_url`, а не дублируются в большом ответе. Параметр
`include_candles=1` включает их в JSON. `timeframe=H4` сокращает структурный ответ;
расчёт целей всё равно использует все четыре timeframe. Все FVG, включая малые,
сохраняются в возвращаемой структуре выбранных таймфреймов.

Порядок для ChatGPT:

1. Получить `/api/market-audit?symbol=...`, проверить `environment`, `quote.fresh`,
   `quote.provider_timestamp`, `reliability`, `warnings` и `consistency`.
2. Читать MN1 → W1 → D1 → H4. Использовать `fractals`, `swept_fractals`,
   `forming_fractals`, `ranges` и остаточные поля `fvgs`; provisional не считать confirmed.
3. Для цели читать `targets.above/below.nearest` и `intermediate_obstacles`.
   `targets.reference_fresh=false` означает, что актуальность опорной цены не подтверждена.
4. Открыть четыре `charts[timeframe].url`, если клиент умеет получать изображения.
   URL возвращает настоящий `image/png`; никакие Capital.com ключи клиенту не нужны.
5. При необходимости загрузить OHLC по `candles_url` или использовать `include_candles=1`.
   Если ответ слишком большой для клиента, запросить структуру отдельных таймфреймов.
6. Формировать собственную макроэкономическую и торговую оценку с учётом предупреждений.

Параметры `min_remaining_units` и `atr_fraction` поддерживаются обоими endpoints.
Слои PNG переключаются 0/1. `bars` ограничен 20–240; это отображаемое окно, расчёты
используют всю загруженную историю. На PNG рисуется до восьми видимых активных FVG с
подписями остатка и заполнения; остальные, включая filled, доступны в JSON.
График и аудит могут быть получены в разные моменты: нужно сравнивать timestamps.

## Производительность, доступ и ограничения

История использует существующий серверный Capital.com transport, лимиты, cooldown,
30-секундный кэш и объединение одинаковых запросов. Таймфреймы загружаются последовательно.
Для аудита котировка запрашивается только по выбранному инструменту, кэшируется пять
секунд, а возраст пересчитывается при выдаче. У PNG ограничены память кэша, число
одновременных рендеров и размер изображения. Рендер не запускает Chromium на Vercel.

Публичные read-only маршруты имеют CORS, no-store и очищенные ошибки. Секреты остаются
на сервере; URL графика не содержит токен. Авторизационная защита Vercel не отключалась:
для внешнего клиента нужен доступ к существующему публичному production-домену.
Кэш и квоты локальны одному процессу, поэтому жёсткий общий лимит при масштабировании
нужно задавать на уровне платформы. Verification-артефакты исключены из Vercel/Docker
build context. Никакие платные сервисы или планы не подключались.

Не выполнено / не подтверждено:

- Публикация новых маршрутов и их успешный вызов на production-домене. Изменения
  находятся в рабочей копии; это не завершённый production-релиз.
- Прямой local end-to-end вызов Capital.com: нужных приватных переменных в локальной
  среде нет. Требуются существующие `CAPITAL_API_KEY`, `CAPITAL_IDENTIFIER`,
  `CAPITAL_API_PASSWORD`, `CAPITAL_API_BASE_URL` через приватную конфигурацию.
- Проверка LIVE-счёта: записанные реальные ответы относятся к DEMO.
- Полнота каждой торговой сессии, синхронность всех снимков, неизменяемый снимок графика
  и непрерывность worker 24/7 не гарантируются этой доработкой. Ранее существовавшая
  инфраструктура архива/worker не менялась.

Подтверждённые структуры относятся к доступной истории. Пропущенные наблюдения могут
скрывать снятия и заполнения; предупреждения нельзя игнорировать. Временной барьер
закрытия рассчитан по уже существующей методике провайдера/номинального периода.

## Воспроизведение

```sh
npm ci
npm test
npm run lint
npm run build
npx playwright install chromium
npm run test:ui
npm run test:analysis-public -- --recorded
# Отдельная актуальная загрузка с существующего публичного сервиса:
npm run test:analysis-public -- https://capitalive.vercel.app
```

Для production требуется публикация в тот же проект `capitalive` с сохранением его
серверных переменных, затем внешний GET к обоим новым маршрутам. Успешная локальная
сборка и доступность старого `/api/structure` не заменяют эту проверку.
