# Multi-TF context и полнота пути

Иерархия MN1 → W1 → D1 → H4 сохранена. Для уровня X исследуются X−1 и X−2:
MN1 → W1/D1, W1 → D1/H4, D1 → H4. Формирование младшего evidence должно быть
позднее подтверждения исходного уровня. Допустимые связанные типы: авторские
RB_TWO_CANDLE, SNR_CLOSED_BREAK, FVG, RAID.

`EXPLICIT_DETECTOR_DEPENDENCY` означает конкретный kl_id/pivot_id. Простое
временное и ценовое пересечение маркируется `CLOSED_INTERACTION_WITH_FORMATION`:
оно не подтверждает причинную реакцию автоматически. Связь имеет ID, TF,
confirmed_at и qualification; сокращённая выдача считает omitted связи.
HTF overlap также не является доказательством авторской значимости.

Если закрытый H4 находится внутри HTF-зоны, а последний наблюдаемый D1/H4 leg
направлен против исходной геометрии этой зоны, контекст показывает
`HTF_GEOMETRY_VS_OBSERVED_LTF_LEG`. Это review conflict, не готовое направление,
не доказанный order flow и не утверждение, что геометрическая support проверена.

Цели B остаются только допустимых типов исходного THE EDGE target selector;
X−2 eligibility сохранена. Candidate Narrative и Confirmed Narrative отдельны.
Entry, KL и Narrative invalidation остаются отдельными полями. Отсутствующий B
не создаётся из ближайшей произвольной цены; Entry/SL/TP не выдумываются.

Пути к B исследуют весь обнаруженный набор четырёх TF до сокращения JSON.
Начало пути — граница выбранной A либо последний закрытый H4, что явно указано
в from_basis. INVALIDATED исключается; CONSUMED может остаться потенциальной
структурной зоной с необходимостью ручной оценки. Это не повторное использование
снятой ликвидности как цели.

- COMPLETE: все требуемые наблюдаемые данные и history покрыты, omissions нет.
- PARTIAL: непроверенное покрытие/история или omitted obstacles.
- UNVERIFIED: нет пригодных endpoints либо отсутствует TF.

Даже COMPLETE не доказывает значимость каждого препятствия и свободный путь:
`free_path_proven` всегда false. Компактный отчёт показывает до трёх B paths и
до четырёх obstacles на путь; total/omitted сохраняются. Для каждого KL на странице
инспектора дополнительно вычисляется approach_path от последнего закрытого H4
до ближайшей границы зоны по всем четырём TF, с полным списком препятствий.
Сам целевой KL из препятствий исключается. Если reference уже внутри зоны,
это обозначено отдельно: внешнего подхода нет, свободный путь не утверждается.
Инспекция ограничена страницей и общим byte ceiling; она не выполняет ручную
оценку значимости препятствий вместо пользователя.

Тесты проверяют causal X−1/X−2, позднее формирование, omission downgrade,
потенциальные consumed obstacles, missing TF/endpoints, конфликт геометрии и
leg. Replay фиксирует все шесть символ/side без изменения старого Narrative.
