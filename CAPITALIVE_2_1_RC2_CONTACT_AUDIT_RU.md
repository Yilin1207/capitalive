## VERIFIED: runtime и snapshot availability

Проверялись фактически запущенные production builds Next на loopback, не только прямой вызов модуля. Данные транспорта — fixtures. В специальном эксперименте свежесть котировки симулируется только тестовым preload; в коде приложения такого override нет. MN1 транспорта собирается из доступной D1-истории и сохраняет флаги неполноты. Полные сохранённые MN1-контрпримеры проверены отдельно.

| Эксперимент с одним snapshot ID | Результат |
|---|---|
| Страница в процессе-владельце A | 200 |
| Та же страница в отдельном процессе B | **410** |
| Та же страница после остановки и нового запуска A | **410** |
| Priority API на B и перезапущенном A | 200 |
| Контакты через Next при симулированной свежести | 3 из 3 допустимых совпадений полного каталога |

Доказательства — `rc2/multiprocess-contracts.json` и журналы серверов. Результат подтверждает **отсутствие** межпроцессной сохранности, а не готовность распределённой пагинации.

В manifest добавлено `availability.mode=best_effort_process_local`, `cross_instance_guarantee=false` и правило восстановления после 410. Ограничения хранения прежние: TTL 10 минут, до 64 MiB на документ и до 96 MiB на процесс. Данные другого снимка не подставляются под старый ID.

Для клиента воспроизведено переключение маршрутизации: manifest и первая страница — A, вторая страница — B. На 410 клиент освобождает частичные chunks, оставляет существующий файл без изменений, сообщает URL `view=priority` и завершает работу с кодом 3. Он не начинает неявный новый снимок и не смешивает страницы. Первоначальная проверка выявила аварийный Windows-код завершения при немедленном `process.exit`; после потребления тела ответа и штатного завершения через `process.exitCode` тест проходит. Неуспешная попытка сохранена в `rc2/attempt-*`.

Выбран рекомендованный аудитом режим best effort с обычным входом UI через priority. Default/full старых API не переименованы и не переключены молча; явный полный download остаётся дополнительной возможностью. Это не замена общему хранилищу, если будущему rollout нужна гарантированная межинстансная выдача.

## LIMITATIONS / UNVERIFIED

Полнота contact относится к **загруженному** каталогу допустимых значимых SNR, не ко всем зонам мирового рынка и не к watch-кандидатам. Precision/recall SNR по независимой полной разметке по-прежнему не установлены; успешные регрессии не доказывают торгового преимущества. Сохранённые DEMO-данные не являются текущими LIVE-котировками.

Не выполнены deployment и эксплуатационный тест целевого Vercel serverless. Локальные два процесса моделируют потерю process-local state и подтверждают поведение клиента; они не доказывают характеристики Vercel, масштабирование, cold-start latency или надёжность общего storage. Гарантированная распределённая выдача snapshots остаётся нерешённой задачей при соответствующем требовании к релизу.
